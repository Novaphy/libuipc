##  Corex （CUDA10.2） 不兼容API影响汇总表

| 名称 | 当前处理方式 | 对系统的影响 |
|---|---|---|
| CUDA Graph 新 API（`cudaGraphUpload` / `cudaGraphInstantiateWithFlags` / `cudaGraphAddMemcpyNode1D`） | `#if CUDART_VERSION >= 11000` 走新 API；Corex 10.2 下退回旧 API/空实现 | Graph 相关能力退化，部分低开销图执行优化不可用，可能带来性能下降 |
| CUB ByKey Scan（`DeviceScan::Exclusive/Inclusive*ByKey`） | 在 `UIPC_COREX_CUDA10_COMPAT` + 低版本 runtime 下编译期隐藏对应封装 | 依赖 ByKey 的算法分支无法启用，需要改写或禁用相关功能 |
| Thrust 执行策略（`thrust::cuda::par_nosync`） | 替换为 `thrust::cuda::par.on(nullptr)` | 无法使用更激进的无同步策略，执行策略保守化，可能出现性能损失 |
| cuSolver Dense 新参数 API（`cusolverDnParams_t` + `cusolverDnXgetrf/Xgetrs`） | 高版本下启用，10.2 下直接报错并返回 | 依赖该接口的 dense 求解路径（如部分 `gesv()` 封装）不可用，相关功能分支缺失 |


### 1 CUDA Graph 新 API 在 10.2 路径不完整

**现象**：在较新 CUDA runtime 才出现的 Graph API，会在 Corex CUDA 10.2 下缺失，导致编译失败。  
**策略**：用 `CUDART_VERSION` 做编译期分支：新版本走新 API，旧版本退化到旧API或空实现。

**示例文件**：

- `external/muda/src/muda/graph/details/graph_exec.inl`
- `external/muda/src/muda/graph/details/graph.inl`


```cpp
#if CUDART_VERSION >= 11000
    checkCudaErrors(cudaGraphUpload(m_handle, stream));
#else
    (void)stream;
#endif
```

**影响**：Corex 10.2 下会禁用/退化部分 Graph 能力。

### 2 CUB `*ByKey` scan 能力缺失

**现象**：Corex 配套 CUB/Thrust 组合下，`cub::DeviceScan::*ByKey` 相关模板实例化会触发编译失败。 

**示例文件**：`external/muda/src/muda/cub/device/device_scan.h`


```cpp
#if !defined(UIPC_COREX_CUDA10_COMPAT) && CUDART_VERSION >= 11000
template <typename KeysInputIteratorT,
          typename ValuesInputIteratorT,
          typename ValuesOutputIteratorT,
          typename EqualityOpT = cub::Equality>
DeviceScan& ExclusiveSumByKey(...){ ... }
#endif
```

**影响**：Corex 10.2 兼容路径下，ByKey scan 封装不可用；普通 `ExclusiveSum/InclusiveSum` 等仍可用。

### 3 cuSolver 新参数 API 不可用

**现象**：`cusolverDnParams_t` + `cusolverDnXgetrf/Xgetrs` 等“新参数 API”在 Corex CUDA 10.2 体系下不可用，直接走新 API 会编译失败。  

**示例文件**：`external/muda/src/muda/ext/linear_system/details/routines/solve/solve_dense.inl`


```cpp
#if CUDART_VERSION >= 11000
    cusolverDnParams_t params;
    cusolverDnCreateParams(&params);
    ...
#else
    MUDA_ERROR_WITH_LOCATION(
        "cusolverDn params API is unavailable on this CUDA runtime; "
        "gesv() is not supported in this backend configuration.");
    return;
#endif
```

### 4 Thrust `par_nosync` 不可用

**现象**：Corex 对应 Thrust 版本不提供 `thrust::cuda::par_nosync`，相关调用会在编译期失败。

**示例文件**：`src/backends/cuda/collision_detection/details/stackless_bvh.inl`


```cpp
auto null_stream = thrust::cuda::par.on(nullptr);
thrust::sequence(null_stream, sorted_id.begin(), sorted_id.end());
```

### 5 Corex LLVM 后端在特定模板组合下不稳定

**现象**：少数 “DeviceReduce + Eigen/向量类型” 组合触发 Corex LLVM 后端代码生成失败。  
**策略**：对这一处顶点包围盒（compute_vertex_bounding_box()）做降级：把数据拷回 host 用 `std::min/std::max` 聚合，绕开后端选择失败。

**示例文件**：`src/backends/cuda/global_geometry/global_vertex_manager.cu`

```cpp
std::vector<Vector3> h_positions(n);
positions.copy_to(h_positions);
for(const auto& p : h_positions)
{
    min_pos_host[0] = std::min(min_pos_host[0], p[0]);
    ...
}
```
