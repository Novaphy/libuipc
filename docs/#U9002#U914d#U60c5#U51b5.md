

## libuipc 在 Corex 上的适配概况

围绕 Corex clang-CUDA 与 NVCC 的差异，已建立专用编译链与参数兼容层，使核心库可在双编译器环境下完成构建与动态加载；并通过编译期开关区分受限设备 API 与替代实现，保证同一套源码在两类目标上可维护。

在 CUDA 能力层面，依据实际支持情况对不兼容或行为不一致的能力做了分支封装与等价替换，覆盖碰撞与接触、稀疏线性代数、部分原子与归约等路径；对设备端代码生成不稳定的场景，采用显式核函数、显式主机/设备声明与局部结构调整等方式规避。

当前后端可在 Corex 上完成链接与运行，示例场景可连续推进多帧，主要求解链路（含 Newton 与迭代线性求解）可正常收敛。由于硬件在双精度浮点上的有效精度与指令语义与常见 GPU 存在差异，接触与约束相关的物理结果仍在与参考环境对照验证，全场景行为一致性属于后续持续加固项。

**单精度构建**：CMake 选项 `UIPC_USE_FLOAT=ON` 定义 `UIPC_FLOAT_SCALAR`，全局 `Float` 为 `float`。CoreX 上 **`muda::ParallelFor` 的设备端 lambda 不可靠**（可能静默不执行），关键路径使用显式 `__global__` kernel 与裸指针（见 `docs/corex-collision-contact-fix-report.md`、`docs/Libuipc在国产平台天数Corex环境上的适配移植（3.27～4.3）.md`）；轨迹 CCD 的 `filter_toi` 在 CoreX 上与 NVIDIA 使用同一套 CCD 公式，由 `corex_filter::kernel_filter_toi_*` 在设备上计算（不做主机回退）。若接触屏障在 float 下过紧，可通过环境变量 `UIPC_FLOAT_D_HAT_SCALE`（正实数乘子）放大配置中的 `contact/d_hat`。
