# Libuipc在国产平台天数Corex环境上的适配移植（3.13～3.20）


## 1. 本周主要工作

### 1.1 主要问题：NVCC 参数集 ≠ Corex clang-CUDA 参数集

**现象**：libuipc/muda 的 CUDA 构建默认以 NVCC 为中心，CMake 会把一批“NVCC 习惯参数”（例如 `-rdc=true`、`-Xcudafe ...`、`--display_error_number` 等）传给 CUDA 编译器。  
在 Corex 环境中 CUDA 前端是 clang 变体，直接接收这些参数会在编译阶段报错。

**策略**：保留项目原有的 CUDA build 组织方式，只在编译器入口进行**最小过滤/转换**，让 clang-CUDA 能接收参数并正确识别 Corex 的 device 语言（`-x ivcore`）。

### 1.2 修改点

#### A) 根 `CMakeLists.txt` 增加 Corex 构建入口

**目的**：把 Corex 相关配置收口到一个 option 下，避免污染常规 NVCC 路径，同时让 Corex clang-CUDA 能接管现有 build.ninja 的参数。

关键改动：

**文件**：`CMakeLists.txt`

```cmake
option(UIPC_MUDA_USE_COREX "Enable Corex-specific CUDA build compatibility mode" OFF)
set(UIPC_COREX_CUDA_STANDARD "17" CACHE STRING "CUDA C++ standard used when UIPC_MUDA_USE_COREX=ON")
set(UIPC_COREX_CUDA_ARCHITECTURES "ivcore11" CACHE STRING "CUDA architectures used when UIPC_MUDA_USE_COREX=ON")
set(UIPC_COREX_CUDA_COMPILER "" CACHE FILEPATH "Path to Corex CUDA compiler (optional)")

if(UIPC_MUDA_USE_COREX)
    if(UIPC_COREX_CUDA_ARCHITECTURES)
        set(CMAKE_CUDA_ARCHITECTURES "${UIPC_COREX_CUDA_ARCHITECTURES}" CACHE STRING "CUDA architectures" FORCE)
    endif()
    if(UIPC_COREX_CUDA_COMPILER)
        set(CMAKE_CUDA_COMPILER "${UIPC_COREX_CUDA_COMPILER}" CACHE FILEPATH "CUDA compiler" FORCE)
    endif()
    set(CMAKE_CUDA_SEPARABLE_COMPILATION OFF CACHE BOOL "Enable CUDA separable compilation" FORCE)
endif()
```

**文件**：`cmake/corex-clang-cuda-wrapper.sh`

```bash
if [[ "$arg" == "-rdc=true" ]]; then
    continue
fi
if [[ "$arg" == "--display_error_number" ]]; then
    continue
fi
if [[ "$arg" == "-Xcudafe" ]]; then
    skip_next=1
    continue
fi
...
if [[ "$is_cuda_input" -eq 1 && "$has_ivcore_lang" -eq 0 ]]; then
    args=("-x" "ivcore" "${args[@]}")
fi
```


#### B) cuda backend 的 CMake 做 Corex 分支

**目的**：避免 CMake 为 CUDA target 加的某些属性/链路在 Corex 下触发不兼容。

**文件**：`src/backends/cuda/CMakeLists.txt`

关键改动：

```cmake
if(UIPC_MUDA_USE_COREX)
    target_link_libraries(cuda PUBLIC dl)
    target_compile_definitions(cuda PUBLIC UIPC_COREX_CUDA10_COMPAT=1)
    set_target_properties(cuda PROPERTIES
        CUDA_SEPARABLE_COMPILATION OFF
        CUDA_RESOLVE_DEVICE_SYMBOLS OFF
    )
endif()
```

## 2. 编译过程问题

### 2.1 主要问题：同一个函数在不同上下文被当成 host-only

**现象**：大量报错显示：

- “calling a __host__ function from a __device__ function is not allowed”
- “no matching function for call …”

**原因（与muda适配中遇到的问题一致）**：

- `MUDA_GENERIC` / `UIPC_GENERIC` 这类宏在 Corex clang-CUDA 下更容易因为包含路径、inline/模板实例化位置、以及 lambda/device 语境而被推断为 host-only；
- libuipc 的 cuda backend 中，distance/friction/collision 等链路调用非常深，任何一个基础函数资格不一致都会引发大量报错。

**策略**：

- 对会同时在 host 与 device 上调用的函数，显式改成 `MUDA_HOST MUDA_DEVICE` / `UIPC_HOST UIPC_DEVICE`；
- 同时保证声明与定义资格一致（避免重载混乱）。

### 2.2 代表性改动

                                                  const Eigen::Matrix<T, M, N>& dst,

## 3. Corex CUDA 10.2 不兼容 API



### 3.1 CUDA Graph 新 API 在 10.2 路径不完整

**现象**：在较新 CUDA runtime 才出现的 Graph API，会在 Corex CUDA 10.2 下缺失，导致编译失败。  
**策略**：用 `CUDART_VERSION` 做编译期分支：新版本走新 API，旧版本退化到旧API或空实现。

**示例文件**：

- `external/muda/src/muda/graph/details/graph_exec.inl`
- `external/muda/src/muda/graph/details/graph.inl`


```cpp
#if CUDART_VERSION >= 11000
    checkCudaErrors(cudaGraphUpload(m_handle, stream));
#else
    (void)stream;
#endif
```

**影响**：Corex 10.2 下会禁用/退化部分 Graph 能力。

### 3.2 CUB `*ByKey` scan 能力缺失：编译期显式禁用封装

**现象**：Corex 配套 CUB/Thrust 组合下，`cub::DeviceScan::*ByKey` 相关模板实例化会触发编译失败。  
**策略**：在 `UIPC_COREX_CUDA10_COMPAT`（以及低版本 runtime）下不暴露对应 muda 封装，避免项目在不需要该能力时被阻塞。

**示例文件**：`external/muda/src/muda/cub/device/device_scan.h`


```cpp
#if !defined(UIPC_COREX_CUDA10_COMPAT) && CUDART_VERSION >= 11000
template <typename KeysInputIteratorT,
          typename ValuesInputIteratorT,
          typename ValuesOutputIteratorT,
          typename EqualityOpT = cub::Equality>
DeviceScan& ExclusiveSumByKey(...){ ... }
#endif
```

**影响**：Corex 10.2 兼容路径下，ByKey scan 封装不可用；普通 `ExclusiveSum/InclusiveSum` 等仍可用。

### 3.3 cuSolver 新参数 API 不可用

**现象**：`cusolverDnParams_t` + `cusolverDnXgetrf/Xgetrs` 等“新参数 API”在 Corex CUDA 10.2 体系下不可用，直接走新 API 会编译失败。  
**策略**：用 `CUDART_VERSION` 做编译期分支：高版本启用新 API；低版本路径直接报错并返回。

**示例文件**：`external/muda/src/muda/ext/linear_system/details/routines/solve/solve_dense.inl`


```cpp
#if CUDART_VERSION >= 11000
    cusolverDnParams_t params;
    cusolverDnCreateParams(&params);
    ...
#else
    MUDA_ERROR_WITH_LOCATION(
        "cusolverDn params API is unavailable on this CUDA runtime; "
        "gesv() is not supported in this backend configuration.");
    return;
#endif
```

### 3.4 Thrust 策略对象差异：`par_nosync` 替换为可用策略

**现象**：Corex 对应 Thrust 版本不提供 `thrust::cuda::par_nosync`，相关调用会在编译期失败。  
**策略**：替换为更保守的执行策略(在默认stream上进行自动同步)。

**示例文件**：`src/backends/cuda/collision_detection/details/stackless_bvh.inl`


```cpp
auto null_stream = thrust::cuda::par.on(nullptr);
thrust::sequence(null_stream, sorted_id.begin(), sorted_id.end());
```

### 3.5 Corex LLVM 后端在特定模板组合下不稳定：局部改为主机侧计算

**现象**：少数 “DeviceReduce + Eigen/向量类型” 组合触发 Corex LLVM 后端代码生成失败（例如 `Cannot select` 一类）。  
**策略**：对这一处顶点包围盒（compute_vertex_bounding_box()）做降级：把数据拷回 host 用 `std::min/std::max` 聚合，绕开后端选择失败。

**示例文件**：`src/backends/cuda/global_geometry/global_vertex_manager.cu`

```cpp
std::vector<Vector3> h_positions(n);
positions.copy_to(h_positions);
for(const auto& p : h_positions)
{
    min_pos_host[0] = std::min(min_pos_host[0], p[0]);
    ...
}
```

## 6. Corex CUDA10.2 不兼容功能影响汇总表

| 名称 | 当前处理方式 | 对系统的影响 |
|---|---|---|
| CUDA Graph 新 API（`cudaGraphUpload` / `cudaGraphInstantiateWithFlags` / `cudaGraphAddMemcpyNode1D`） | `#if CUDART_VERSION >= 11000` 走新 API；Corex 10.2 下退回旧 API/空实现 | Graph 相关能力退化，部分低开销图执行优化不可用，可能带来性能下降 |
| CUB ByKey Scan（`DeviceScan::Exclusive/Inclusive*ByKey`） | 在 `UIPC_COREX_CUDA10_COMPAT` + 低版本 runtime 下编译期隐藏对应封装 | 依赖 ByKey 的算法分支无法启用，需要改写或禁用相关功能 |
| Thrust 执行策略（`thrust::cuda::par_nosync`） | 替换为 `thrust::cuda::par.on(nullptr)` | 无法使用更激进的无同步策略，执行策略保守化，可能出现性能损失 |
| cuSolver Dense 新参数 API（`cusolverDnParams_t` + `cusolverDnXgetrf/Xgetrs`） | 高版本启用，10.2 下直接报错并返回 | 依赖该接口的 dense 求解路径（如部分 `gesv()` 封装）不可用，相关功能分支缺失 |
| cuSolver Sparse 句柄（`cusolverSpCreate` 返回 `CUSOLVER_STATUS_NOT_SUPPORTED`） | 将 `cusolverSp` 能力改为可选：失败时置空句柄并跳过后续 `cusolverSpSetStream` | Sparse 求解相关能力不可用或受限；若路径强依赖 `cusolverSp`，将无法工作 |
| cuBLAS 符号（`cublasNrm2Ex`） | `float/double` 回退 `cublasSnrm2/cublasDnrm2`，其他类型仍保留 `Nrm2Ex` | 使用 `Nrm2Ex` 的路径会被阻断；常见 `float/double` 可恢复，混合精度等特殊类型仍受限 |
 RDC / Device Link（`-rdc=true`、`CUDA_SEPARABLE_COMPILATION`） | Corex 模式下过滤 `-rdc=true` 并关闭 separable compilation / resolve device symbols | 跨 `.cu` 的 device 符号链接能力受限；出现跨 TU device 依赖时需结构性改写（header 化/inline 化） |
